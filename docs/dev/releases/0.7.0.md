# Tabalyst 0.7.0

Tabalyst 0.7.0 reworks Scan and the JSON formats around three ideas: Simple
(one clear scan document), Clear (what is exact, estimated or limited is
stated) and Smart (extra work is chosen by deterministic budgets and asked for
when costly). It also moves Tabalyst Generate to a package format and adds the
Computer example. This note describes the release contents; the commit, tag and
publication are separate steps.

## Highlights

- **Scan document.** Values carry their accuracy and domain. Cardinality names
  how it was counted and where tracking stopped. Each field keeps a bottom-k
  sample of its original values (10,000 by default, `scan.limits.max_samples`)
  with a KMV estimate of the distinct count when the exact table overflowed,
  samples by length, a bounded preview of long texts, and a memory budget for
  all samples. A row sample keeps the first, interior and last rows.
- **Findings.** Structural patterns inferred from the samples, observations and
  quality issues, and adaptive normalization. A new JSON Schema ships for every
  format (`tabalyst.scan`, `tabalyst.report`, `tabalyst.scan.deep`,
  `tabalyst.sample`).
- **Scan page.** An explicit `tabalyst scan` writes `<stem>.scan.html`, a page
  rendered from the Scan alone; `--no-html` turns it off.
- **Second pass.** `tabalyst scan --plan` shows the analyses a second reading
  of the source would add, with their estimated cost; `tabalyst scan --deep`
  runs it into `<stem>.deep.json`: exact histograms and quantiles, exact
  distinct counts and frequencies, patterns counted on every occurrence, dates
  per period, correlations between numeric columns, and tables of a category
  against a feature. `tabalyst report` decides by itself whether a second pass
  is worth its cost; `report --deep` forces it. A costly run shows its estimate
  and asks first; outside a terminal it stops unless `--yes` is given.
- **Report.** The Report profile is a superset of the Scan document. The HTML
  report reads the findings of the scan and adds the Relationships and Second
  pass sections and the validated occurrences of each pattern.
- **Stratification advice.** `tabalyst scan --plan --stratify` assesses strata
  before a stratified sample.
- **Smart sample.** `tabalyst sample --sample-method smart` selects rows that
  cover the cases of the file, not its proportions. It writes a report
  (`<stem>.sample.json`, format `tabalyst.sample`) and a page
  (`<stem>.sample.html`). `tabalyst scan --plan --smart` shows its plan.
- **Workers.** At most 6 worker processes by default; the second pass of a CSV
  file also runs in workers (`--workers` applies to both passes). Workers load
  a smaller part of the package.
- **Generate.** Examples and user definitions are Generate packages (a
  `dataset.yaml`, a `catalog.yaml`, schemas and CSV tables). The new `computer`
  example writes English and French files of the same computer offers, with
  compact, standard and extended column profiles (40, 70, 111), markets,
  generation profiles, anomaly profiles, and measurements as numbers or with
  units. `--validate-only`, `--request`, `--generation-profile`,
  `--output-profile`, `--market`, `--locales`, `--unit-style` and
  `--unit-columns` are new.

## Compatibility

- **Formats (experimental).** Scan and Report move from revision 1 to
  **revision 2** of format 0.2.0, Inspect stays at revision 1. The Second pass
  document (`tabalyst.scan.deep`) and the smart sample report
  (`tabalyst.sample`) start at revision 1. Tabalyst does not migrate: a Scan or
  Report written by 0.6.2 is refused: scan the source again. Changes are listed in
  `docs/en/scan/format-changelog.md` and `docs/en/report/profile-changelog.md`.
- **Report JSON.** The profile now has `format: "tabalyst.report"`, the scan
  base at the same paths and the report data under `report`; the copies of scan
  facts in columns (`scan_details`, `numeric`, `string_profile`,
  `date_profile`) are removed. Scripts that read the profile must change.
- **Configuration.** `scan.limits.max_samples` defaults to 10,000 (100 before)
  and is at most `max_distinct_per_field`. Presentation settings of the Report
  move under a `report` object. New `deep` and `smart` objects.
- **Generate.** The `definition_version: 1` YAML files of 0.6.2 are no longer
  read: the command stops with `PACKAGE_FORMAT`. There is no conversion; use a
  package. The Python functions `build_generate_plan()` and
  `generate_datasets()` take the same package inputs.
- **Size.** The JSON documents are larger because they keep samples: for the
  3,000-row, 34-column example, the Report profile goes from about 0.5 MB to
  2.8 MB and its Scan is 2.6 MB.

## Performance

Measured on the one-million-row, 34-column reference file, interleaved with
the previous engine on the same machine. These are not guarantees.

- First pass: +14.5 % time on the realistic case (threshold 20 %), +7 % total
  memory (719 to 769 MB, workers included).
- `tabalyst report` with an automatic second pass costs about 59 % more than
  without one.
- Memory of the first pass does not grow with the number of rows, except for
  the table of row fingerprints, which `limits.max_tracked_records` bounds
  (2 M). The complete benchmark matrix (21 cases, up to 2 M rows or 1,000
  columns at 200,000 rows) is in `docs/dev/scan/benchmarks.md`.
