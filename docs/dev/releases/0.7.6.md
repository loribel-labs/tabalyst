# Tabalyst 0.7.6 (in preparation)

Tabalyst 0.7.6 counts the combinations of missing values of a dataset, names the blocks of columns that go missing
together in the report, and adds the first chart page to `--details`. It follows 0.7.5. Other changes are planned for
this version; this note describes what is on `main` so far. The version, the tag and the publication are separate
steps, kept apart:

| Step | State |
| --- | --- |
| Prepared (code, tests, documentation, this note) | In progress, on `main` |
| Version set in `pyproject.toml` | No (0.7.5) |
| Tagged | No |
| Published to PyPI | No |

## Highlights

- **Combinations of missing values.** The second pass gains `missing_patterns`: for each dataset, the exact set of columns
  each record lacks a value in, counted in the same reading as `missing_matrix`, which it shares. Each record counts in
  one combination only, as an UpSet plot draws them. The combinations tracked are bounded (`deep.missing.max_patterns`,
  1,000), each exact from its first record; the records of later ones are summed as `untracked`. Never automatic: ask
  for it with `--deep`, `--details` or `AnalysisRequest("missing_patterns")`.
- **Blocks in the report.** The *Columns missing together* card of the dataset names the largest groups of columns that
  go missing together (at least 80% of the records that lack any one of them lack all, and at least 1% of the records;
  five at most), with the records with every value, those that lack one, the combinations seen and the first 15
  combinations. On the CRM example: `opportunity_amount`, `opportunity_probability` and `opportunity_close_date`.
- **Chart pages.** `--details` writes `charts-missing.html` beside the column pages: per dataset, an UpSet plot drawn
  with Apache ECharts (sort, filter, one bar per combination on a narrow screen) and the tables of the same figures.
  The report links to it from the card and its navigation, and the page of a column that lacks values links to it.

## Changes of behavior

- **`--details` runs the second pass.** It forces it as `--deep` does: a script that used `--details` outside a terminal
  on a file whose second pass is costly now stops with exit code `3` unless it adds `--yes`, and with `--scan` the
  source must be beside the scan document (exit code `4` otherwise). With `deep.mode` `off` in the configuration,
  `--details` is an error.
- **The chart pages load a library from a CDN.** `charts-missing.html` loads Apache ECharts 6.1.0 from jsDelivr, pinned
  by its SRI hash, without a referrer; no data of the report leaves the page. Offline, its charts show a message and
  its tables stay. `report.html` and the column pages still load nothing from outside.
- **`--force` without `--details`** also removes the chart pages written earlier, as it removes the column pages; only
  the pages Tabalyst generated.

## Compatibility

- **Formats.** The second-pass document is at revision 5 and the Report profile at revision 6: a new result kind
  `missing_patterns` in `analyses`. The schemas are regenerated. Inspect and the Scan document are unchanged.
- **Settings.** `deep.missing.max_patterns` (1,000) and `deep.missing.max_patterns_listed` (200).
- **Planner.** `COST_MODEL_VERSION` 22 (the measured cost of the combinations).
- **Python API.** `render_report()` gains the optional `chart_links`; `details=True` in `analyze()` and
  `generate_reports()` forces the second pass, as `deep=True`, and needs `confirmed=True` when it is costly.
