# Tabalyst 0.7.5

Tabalyst 0.7.5 ties the columns of the Tabalyst Generate examples together and adds a `rule_breaks` profile to each,
so that the generated files can test analyses across columns. It follows 0.7.4. This note describes the release
contents; the commit, tag and publication are separate steps, kept apart:

| Step | State |
| --- | --- |
| Prepared (code, tests, documentation, this note) | Yes, on `main` |
| Version set in `pyproject.toml` | Yes (0.7.5) |
| Tagged | No |
| Published to PyPI | No |

## Highlights

- **No exception in the clean files.** The rules between columns of the CRM, Insurance and Computer examples hold on
  every row of a clean file; exceptions come only from an anomaly profile, which logs them.
- **`rule_breaks` in every example.** It leaves the formats alone and breaks those rules on purpose, each change named
  by a `class` in the change log: 7 classes for CRM, 9 for Insurance, 7 for Computer.
- **CRM.** Log-normal deal amounts (median about 18,000) with a monthly factor, a factor by company size and 60% of the
  amounts rounded to the hundred; probability and lifecycle stage by opportunity stage; dates in order, contacts growing
  by 25% a year, no activity on weekends; owners by province; a 35% opt-in; missing values that depend on other columns.
  `dirty_realistic` gains five defects (two currency forms, day-first dates, a trailing space, lower case).
- **Insurance.** Travel contracts of 3 to 90 days; the claim status follows the claim's age; log-normal claim amounts;
  the modification date follows the claim; monthly payments are direct debits or cards; the agency of the customer's
  city; premiums and missing emails by age.
- **Computer.** Reviews come with time: about 30% of the products released less than a year ago have no review yet, so
  no rating.
- **Column model.** A Generate package can declare `distribution: lognormal`, `by_month`, `by_value` and `round_to` on a
  `decimal`, `by_case` on `choice`, `integer`, `decimal` and dates, `after`, `growth` and `weekdays` on dates,
  `true_share` on a `boolean` and `missing_by` on a column.

## Compatibility

- **Data change.** The three examples write different files for the same seed. A package that does not use the new
  options writes the same bytes as before.
- **Formats.** No format changes: the Generate package format stays `0.1.0` and the new keys are optional; the Report,
  Scan and Inspect formats are unchanged.
- **Scan and Report** still do not evaluate rules between columns: the files illustrate them.

The decision is recorded in `docs/dev/adr/2026-11-11-generate-cross-column-rules.md`.
