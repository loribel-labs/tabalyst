# Tabalyst 0.7.4

Tabalyst 0.7.4 gives Tabalyst Sample a quota per value and a guaranteed minimum for the proportional sample. It
follows 0.7.3. This note describes the release contents; the commit, tag and publication are separate steps, kept apart:

| Step | State |
| --- | --- |
| Prepared (code, tests, documentation, this note) | Yes, on branch `chore/release-0.7.4` |
| Version set in `pyproject.toml` | Yes (0.7.4) |
| Tagged | No |
| Published to PyPI | No |

## Highlights

- **`stratified-balanced`.** `--sample-method stratified-balanced --field F --per-value N` (Python: `per_value`) keeps
  `min(N, rows of the stratum)` random rows of each stratum, without replacement and without moving unused places to
  another stratum, in one reading. The size is the sum over the strata. `--rows` and `--percent` are refused.
- **`stratified` keeps a row of each stratum.** The allocation holds a stratum whose exact quota is under one row at
  one, takes the cost from the others in proportion, and shares the rest by the largest remainder with integers only.
  The total is exact and no stratum exceeds its population.
- **Clear refusal.** A size under the number of strata stops with an error that names the `--rows` needed; nothing is
  written.

## Compatibility

- **Behavior change.** `stratified` with a size under the number of strata, accepted until 0.7.3, is now an error (exit
  code 4). Samples made with 0.7.3 can differ.
- **Formats.** No format changes.
- **API.** `sample_csv()` and `generate_samples()` gain `per_value`; `SampleResult` gains `per_value` and
  `strata_capped`; `SampleMethod.STRATIFIED_BALANCED` is new. The planner advice keeps `uncovered_at_size` (strata
  beyond the size) and `size_for_every_stratum` (now the number of strata).

The decision is recorded in `docs/dev/adr/2026-11-03-sample-stratified-minimum-and-balanced.md`.
