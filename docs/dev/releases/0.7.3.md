# Tabalyst 0.7.3

Tabalyst 0.7.3 makes Tabalyst Generate fast and simple to use for the Computer example: 30,000 rows with errors in
two languages take about 17 seconds instead of 8 minutes, and one command can write one CSV with errors or one variant per level
of errors. It follows 0.7.2. This note describes the release contents; the commit, tag and publication are
separate steps, kept apart:

| Step | State |
| --- | --- |
| Prepared (code, tests, documentation, this note, demos) | Yes, on branch `perf/generate-selection-cache` |
| Committed | Yes (the release preparation itself is committed with this note) |
| Version set in `pyproject.toml` | Yes (0.7.3) |
| Tagged | No |
| Published to PyPI | No |

The number 0.7.3 is the maintainer's choice (a patch version that improves an existing tool during the beta).

## Highlights

- **Speed.** The selection of the rows of Computer caches what depends only on the remaining steps (feasibility,
  candidates, weights), and the derivation uses indexes. 30,000 rows with `dirty_realistic` in both languages
  (`-d`): 486 s before, about 17 s in one process. The output for a seed is byte for byte the same as in 0.7.2.
- **Worker processes.** From 5,000 rows, Computer renders its rows in worker processes (`--workers N`; by default one
  per spare processor, at most 6; 1 keeps one process). Same files whatever the number. 30,000 rows: about 8 s with
  three processes; 1,000,000 rows: about 3 min.
- **One file.** `-o FILE.csv` is valid for Computer: one locale (English by default), and with one anomaly profile the
  file holds the errors and `FILE.changes.csv` lists the changed cells.
- **One locale.** `--locales en` or `--locales fr`, which the earlier option text promised but the command refused.
- **Several levels of errors.** `--anomaly-profile dirty_realistic,dirty_stress` (or a list in a request file) with
  `-d` writes one variant per profile from a single generation of the rows.
- **Progress and time.** A rewritten progress line on a terminal, with the time left (`--no-progress` hides it), and a
  closing line with the rows, total time, rate, changed cells, processes and where the time went.
- **Clearer errors and help.** An unknown anomaly or generation profile lists the available names; the help of
  `--anomaly-profile` names the Computer profiles.

## Compatibility

- **Formats.** No format changes: the Report profile, the Scan document and the Dedup report are untouched. The same
  package, options and seed give the same CSV files as 0.7.2.
- **Metadata.** `computers.meta.json` keeps its layout for one anomaly profile; with several it lists them under
  `request.anomaly_profiles` and `anomalies.<locale>.<profile>`. With one locale, `request.locales` and `outputs`
  list that locale only.
- **API.** `generate_datasets(plan, on_progress=None)` and `build_generate_plan(..., workers=None)` are new.
  `GenerateResult` gains `seconds`, `timings` and `workers` (with defaults). `ComputerPlan.anomaly_profile` is now a
  property over `anomaly_profiles`, which replaces the constructor field.
- **Errors.** `-o` for Computer used to fail with "Computer produces multiple artifacts; use -d"; a request that
  passed `locales` other than `["en", "fr"]` used to fail and now writes that locale.

## Performance

Measured on one machine (Linux, 4 processors, local disk) with `dirty_realistic`. Not guarantees. The first row
uses `-d`, which writes both languages, so it does twice the writing and the error injection of the others, which
use `-o` (one language).

| Rows | 0.7.2 | 0.7.3, one process | 0.7.3, three processes |
| ---: | ---: | ---: | ---: |
| 30,000 (`-d`, two languages) | 486 s | 17 s | 8.0 s |
| 300,000 (`-o`) | not measured | 2 min 25 s | 56 s |
| 1,000,000 (`-o`) | not measured | 8 min 1 s | 3 min 4 s |

Peak memory stayed at 69 to 76 MB from 300,000 to 1,000,000 rows (the main process; each worker adds about 40 MB).
The CSV of 1,000,000 rows is 366 MB and its change log 29 MB.

## Known limits of this release

- Error injection is sequential: about 27 s for 1,000,000 rows and each additional profile or locale.
- Several anomaly profiles need `-d`; `-o` takes one.
- The synthetic values keep their simple rules (constant weight per computer type, uniform ratings and review
  counts, 69 models): they encode consistency, not market estimates.
- CRM and Insurance are unchanged: no `-o` with an anomaly profile, no workers.
