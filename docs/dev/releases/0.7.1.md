## Highlights

- **Tabalyst Dedup.** `tabalyst dedup` finds the rows of a CSV file that occur more
  than once, with an exact comparison of every cell (case, spaces and leading zeros
  count), and writes up to three CSV files beside the source or in `-d`:
  `<stem>.unique.csv` (every distinct row once, at its first place),
  `<stem>.duplicates.csv` (each repeated row once) and, when a row occurs three times
  or more, `<stem>.duplicates_all.csv` (every occurrence of the repeated rows). A source
  without duplicate gets its report only. The source is never modified.
- **Exact or failed.** A `complete` report is exact. The rows are kept in memory up to
  `--memory-budget-mb` (512 by default), then in a temporary SQLite database; a source
  holds 10,000,000 records by default (`--max-rows`); a source that changes during the
  run, a full disk or a malformed CSV fails with a stable `reason` and publishes nothing.
- **Reports.** `<stem>.dedup.json` (`tabalyst.dedup`, format `0.2.0` revision 1, JSON
  Schema `tabalyst.dedup.schema.json`) holds the counts, which always add up, and the
  inventory of the files written (name, rows, size, SHA-256). A batch (a pattern or
  several inputs) also writes `dedup.summary.json` (`tabalyst.dedup.batch`, revision 1,
  schema `tabalyst.dedup.batch.schema.json`).
- **Batches and incremental runs.** Derived files (`.sample.csv`, `.unique.csv`,
  `.duplicates.csv`, `.duplicates_all.csv`, `.dedup.json`, `dedup.summary.json`) found
  by a pattern are skipped, never an error. A source that is already processed and
  unchanged is `SKIPPED` (decided by size and modification time, or by SHA-256 with
  `--verify-content`). `--force` processes again. A file under an output name that no
  Dedup report proves it wrote is refused without `--force`, and a source is never
  replaced. The CSV are published first and the report last; a run that is interrupted
  is repaired by the next one.
- **Python.** `tabalyst.dedup_csv()` and `tabalyst.generate_dedups()` with
  `DedupResult` and `BatchDedupResult`.
- **Configuration.** A `dedup` object (`max_rows`, `memory_budget_mb`,
  `verify_content_on_skip`); the `csv` object also configures `dedup`.
- **Shared CSV reading.** `tabalyst.csv_records` holds the CSV reading and writing
  conventions that `sample` and Dedup share, without a change of behavior of `sample`.
- **Documentation.** `docs/en/dedup/` (overview, batches, exactness and limits, report
  format and changelog), the `tabalyst dedup` and `tabalyst.dedup_csv()` references,
  glossary entries and a pointer from the known limitation of the duplicate count of the
  Scan to Dedup.

## Compatibility

- **Exit codes of `tabalyst dedup`.** `0` nothing failed, `1` a failure that is not an
  input error (or an unwritable batch report), `2` an invalid option or configuration,
  `4` a missing source or only input errors. Code `3` is not used: Dedup never asks.
- **Formats (experimental).** `tabalyst.dedup` and `tabalyst.dedup.batch` start at
  `0.2.0` revision 1. The other formats do not change.
- **Existing commands.** `scan`, `report` and `sample` are unchanged. They do not yet
  skip the files Dedup wrote when a pattern finds them (`*.csv` also reads
  `customers.unique.csv`).

## Performance

Measured on one machine (24 logical processors, 31 GB, NVMe SSD, Windows 11,
Python 3.12), rows of 4 cells, 25 % of extra copies. These are not guarantees; the
numeric budgets are proposals until the maintainer validates them.

| Records | Mode | Time | Peak working set |
| ---: | --- | ---: | ---: |
| 1,000,000 | memory | 3.5 s | 210 MiB |
| 5,000,000 | disk | 34 s | 527 MiB |
| 10,000,000 | disk | 96 s | 596 MiB |

The working set stays under the budget plus about 150 MiB. The counts agree with an
independent `GROUP BY` of every cell (DuckDB) on the 50 benchmark cases, and with the
Scan under its limit (`limits.max_tracked_records`). The full tables are in
`docs/dev/dedup/design.md` section 18 and the scripts in `tabalyst-lab/benchmarks/`.

## Known limits of this release

- No lock: two simultaneous runs on the same outputs are not protected.
- No check of the space for the outputs before the run.
- A cell over 131,072 characters fails its source with `invalid_csv`.
- `--verbose` measures the memory peak with `tracemalloc`, which slows the first pass
  two to four times.
- Excluding derived files from `scan`, `report` and `sample` patterns, `sample
  --distinct` and the reuse of Dedup by `scan --deep` are later work.
