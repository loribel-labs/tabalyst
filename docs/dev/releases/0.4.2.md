# Tabalyst 0.4.2

Tabalyst 0.4.2 makes Tabalyst Scan, and so `tabalyst report`, several times
faster on large files, uses the processors of the machine for files of 16 MiB
or more, stops testing detectors whose early matches have died out, and
reduces horizontal scrolling in wide reports. Results do not change, apart
from the counts of those rare detectors.

## Highlights

- Faster scans. One million rows of 20 columns take about 12 s instead of
  147 s with 0.4.1 and 109 s with the pandas engine of 0.3.0; 100,000 JSON
  records take about 8 s instead of 22 s. In one process, the million rows
  take about 38 s with the memory of 0.4.1.
- Distinct values are analyzed in batches, detector by detector: most values
  are rejected by a quick check without a call per value, a skipped detector
  costs nothing, and an enumeration that can no longer match stops. CSV
  records are read in batches of rows and counted column by column.
- Worker processes. Files of 16 MiB or more are analyzed by one worker
  process per spare processor, at most 8, each handling whole fields, with the
  same result as one process. `tabalyst scan` and `tabalyst report` accept
  `--workers N` (`--workers 1` keeps one process), and `tabalyst.scan()`,
  `tabalyst.generate_scans()`, `tabalyst.generate_reports()` and
  `tabalyst.analyze_csv()` accept `workers=`. Workers are plain subprocesses:
  a script that calls Tabalyst without an `if __name__ == "__main__":` guard
  is never run again.
- Rare detectors. After the warm-up of adaptive detection, a detector that
  recognized at most `scan.detection.rare_share` of the first distinct values
  (default 0.001, 10 of 10,000), and none in the second half of the warm-up,
  also stops testing the other values of the column. A detector still
  recognizing values at the end of the warm-up, as in a sorted column, keeps
  testing, and so does a sensitive detector that found only invalid values.
- Wide reports scroll less. The report uses up to 1,760 px of width instead
  of 1,440 px, table headers wrap before a table needs to scroll, and in the
  data sample long column names break after `_`, `.`, `-` or `/` and lists
  of JSON values wrap. At 1,920 px, only data samples with many columns still
  scroll horizontally.

## Behavior changes

- Counts of rare detectors may be lower on columns with more than 10,000
  distinct values: their values after the warm-up count as `not_tested`, and
  the new `adaptive.warmup_reactions` says how many warm-up values they
  recognized. Types, semantic types and masking do not change. Set
  `scan.detection.rare_share` to `0` for the behavior of 0.4.1.
- Large scans start worker processes. Memory stays bounded by the scan limits
  in each process, about 60 to 80 MB more per worker.

## Format compatibility

The analysis profile remains in format family `0.1.0a` and moves from
revision `7` to revision `8` (new `rare_share` setting). The scan document
moves from revision `3` to revision `4` (`adaptive.warmup_reactions`, new
setting); `tabalyst report --scan` reads revision 4 only, so scan older
documents again. The execution-history schema remains `1.0`.
