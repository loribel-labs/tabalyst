# Tabalyst 0.4.0

Tabalyst 0.4.0 introduces Tabalyst Scan, a streaming analysis engine for CSV
and JSON sources, and rebuilds Tabalyst Report on it. Reports now cover JSON
files, run in bounded memory and no longer depend on pandas.

## Highlights

- Added `tabalyst scan INPUT... [OPTIONS]`, which writes a `<stem>.scan.json`
  document for CSV and JSON sources, with `-o`, `-d`, repeatable `--config`
  and `--collection`, `--delimiter`, `--encoding`, `--force`, atomic writes
  and batches that continue after a failed source.
- Added the public `scan()`, `generate_scans()`, `ScanConfig` and `ScanResult`
  Python APIs. Configuration files accept a `scan` section, validated by every
  command and merged in order.
- Added streaming readers for CSV and JSON with automatic and explicit
  collections, structural limits, exact cardinality with proven bounds,
  numeric statistics, normalization stages with variant groups and scan
  limits that report proven lower bounds instead of failing.
- Added detectors for numbers, dates, booleans, enumerations, emails, URLs,
  phones (North America, France), postal codes (Canada, United States),
  currencies, percentages, quantities, UUIDs and IP addresses, plus
  declarative `pattern:<id>` detectors. Sensitive fields are masked by default.
- Rebuilt `tabalyst report` on Tabalyst Scan in one streaming pass. Reports of
  JSON files show one view per dataset with a dataset selector.
- Added `tabalyst report --scan data.scan.json` to build a report from a scan
  document without reading the source; stale scans are refused.
- Added the report sections "Detectors and formats", "Transformations",
  "Limits and diagnostics" and, for JSON reports, "JSON structure".
- Duplicate records are counted in streaming within the
  `scan.limits.max_tracked_records` budget.
- Removed the pandas engine and the pandas dependency. `ijson` is a new
  runtime dependency and the minimum Pydantic version is 2.11.

## Breaking changes

- The analysis settings of the report moved to the `scan` object of
  configuration files; former keys are rejected with their new location.
- `analyze_column` and `AnalysisConfig` were removed.

## Format compatibility

The analysis profile remains in format family `0.1.0a` and moves from
revision `2` to revision `6` (see the profile format changelog). The scan
document is in format family `0.1.0a`, revision `2`. The execution-history
schema remains `1.0`.
