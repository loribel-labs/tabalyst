# Tabalyst 0.7.2

Tabalyst 0.7.2 qualifies the identifier columns of a Report: the repetitions of an ID that exact
copies of whole rows explain are told apart from those between distinct records. It follows 0.7.1
(Tabalyst Dedup, published). This note describes the release contents; the commit, tag and
publication are separate steps, kept apart:

| Step | State |
| --- | --- |
| Prepared (code, tests, documentation, this note) | Yes, on branch `unique-id/phase-1` |
| Committed | Yes (lots 0 to 10); the release preparation itself is not |
| Version set in `pyproject.toml` | Yes (0.7.2) |
| Tagged | No |
| Published to PyPI | No |

The number 0.7.2 is the maintainer's choice (a patch version that adds a capability during the beta).
Phases P0 and P1 of the Unique ID project ship together; P0 was never published alone.

## Highlights

- **Identifier uniqueness.** Each column of role `identifier/id` or `identifier/unique_id` gets
  `summary.identifier_uniqueness` in the Report JSON: raw uniqueness, uniqueness after row
  deduplication, the repetitions explained by exact copies of rows and the residual ones between
  distinct records. Exact integers and codes only; the raw finding `identifier.repetition` and the
  Scan classification do not change.
- **Evidence.** The Scan's exact counts, then the second pass, then a Dedup report. A Dedup report
  is used only after its identity is validated (source digest, delimiter, encoding, row identity,
  totals). `report --dedup-report <file or folder>` (API parameter `dedup_report`, key
  `report.dedup_report`) picks it; the `<stem>.dedup.json` beside the source is found by itself.
  Two exact sources that disagree give a local `failed` / `evidence_conflict`.
- **Second pass.** Two analyzers: `duplicate_rows_count` (the extra copies of whole rows, counted
  with the Dedup engine in a mode that writes nothing) and `analytical_distinct` (the exact count of
  distinct values after `nfc`, `trim` and `collapse_whitespace`). The planner chooses them by itself
  for an identifier candidate when the cost is low and a valid Dedup report does not already give the
  answer; a forced run asks first.
- **Missing IDs.** `missing_id_copies` counts the copies of rows that lack an ID, so the residual
  repetitions are exact among the rows that have one (`unique_among_present_ids`).
- **Near-unique reading.** For a residual of a few repetitions among many distinct rows, a
  non-binding `near_unique` reading (`T(U) = min(U // 100, isqrt(U), 1000)`). Never a guarantee,
  never a role.
- **Page.** A card on the column page, a short line in the Summary and a link from the raw finding.

## Compatibility

- **Formats (experimental).** Report profile `0.2.0` revision 5 (was 4); second-pass document
  `tabalyst.scan.deep` revision 4 (was 3). Tabalyst does not migrate: make the documents again.
  The Scan document and the Dedup report do not change.
- **Cost model.** `COST_MODEL_VERSION` 21: plans and cached second-pass results from 0.7.1 are
  recomputed.
- **Existing commands.** `report --dedup-report` is new; an unusable value (non-CSV source, missing
  path, folder without the report, file for several sources) is an error, never ignored.
  A `report --deep` that keeps the copies count asks for confirmation.

## Performance

Measured on one machine (Windows 11, one process), 4 columns of about 50 bytes. Not guarantees.

| Records | Storage | Count of the copies |
| ---: | --- | ---: |
| 1,000,000 | memory | 1.6 s |
| 5,000,000 | disk | 28 to 31 s |
| 10,000,000 | disk | 57 to 80 s |

The Report itself stays under a second at 10 M records with a Dedup report (the CSV is not opened).
The full tables are in `docs/dev/report/identifier-uniqueness.md` section 12.

## Known limits of this release

- With the default limits the Scan keeps the copies exact up to 2,000,000 records, and the automatic
  count fits about 500,000: a larger file needs `--deep`, a Dedup report or a Scan that tracked it all.
- Above 100,000 distinct IDs the Scan estimates the distinct count: the uniqueness stays `limited`
  until `analytical_distinct` or an exact count runs.
- The near-unique constants are provisional (no real file to calibrate them on).
- Not delivered: composite keys, discovery of candidate identifiers, Smart or Explore advice (P2).
